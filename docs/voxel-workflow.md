# Voxel workflow

Rogue Tower's models are MagicaVoxel exports: static meshes, one 256×1 palette texture each, 0.1 world units per voxel for buildings. Treasure Run works with `.vox` files directly: no Unity Editor, no AssetBundles.

## Folders

| Folder | Content | In git? |
|---|---|---|
| `RogueTower/Ripped` | AssetRipper export of the game | no (game assets) |
| `RogueTower/Voxels` | All vanilla models as `.vox` + `.json` + preview `.png` (generated by VoxTool) | no (game assets) |
| `TreasureRun/models` | **Our own** models, copied into the plugin on every build | yes |
| `BepInEx/plugins/TreasureRun/models` | What the game loads (deploy target) | – |

Inside `models/`:
- `overrides/`: replaces vanilla meshes (see below).
- Anything else: models used by mod code by name, e.g. `towers/fighter_jet` → `models/towers/fighter_jet.vox`.

```bash
TreasureRun/tools/VoxTool/bin/Release/net8.0/VoxTool.exe extract Ripped/ExportedProject/Assets Voxels --scene GameScene
```
```bash
TreasureRun/tools/VoxTool/bin/Release/net8.0/VoxTool.exe preview path/to/model.vox
```

- **`extract`** converts every prefab model (or `--scene <name>`; `--filter <text>` limits it). Each model gets three files:
  - `.vox`: open it in MagicaVoxel.
  - `.json`: placement data, see below.
  - `.png`: isometric front/back preview.
- **`preview`** renders a `.png` for any `.vox`. That's how Claude checks models it generates.
- **`info`** prints size, voxel count and colours.

Notable extracted models:
- `Voxels/GameScene/MainTower_default.vox`: the castle.
- `Voxels/BiPlane/…`: the biplane.
- `Voxels/<Tower>/…`: towers. They're usually split into a base and a turret.

Terrain tiles and the platonic-solid enemies aren't voxel art and come out without colours.

## The .json sidecar

```json
{ "VoxelSize": 0.1, "Origin": [-0.8, 0.3, -0.8], "Source": "BiPlane/Art/RotationOffset/BiPlane/default" }
```

- **VoxelSize:** world units per voxel. Keep 0.1 for buildings so new models match vanilla.
- **Origin:** position of the voxel grid's corner in the object's local space. Extracted models keep their exact vanilla placement. Without it, a model is centred on X/Z and stands on Y = 0.
- **Source:** the vanilla renderer this model came from. Only needed for overrides.

New models don't need a sidecar at all.

## Replacing a vanilla model (overrides)

1. Copy an extracted pair, e.g. `Voxels/BiPlane/BiPlane_..._default.vox` + `.json`, into `models/overrides/` (any file name).
2. Edit the `.vox` in MagicaVoxel. Keep the grid size if the placement should stay identical.
3. Build the plugin, or copy the files into the deployed `models/overrides` folder directly.
4. Start a Treasure Run. Overrides apply when the run starts and are undone when it ends. **F6** reloads all models while playing.

Prefab overrides (towers, planes, enemies) affect every instance spawned afterwards. Scene overrides (`GameScene:…`, e.g. the castle) affect that object.

## Using models from code

```csharp
GameObject go = VoxelLibrary.Spawn("towers/fighter_jet", position, rotation, parent);
VoxAsset asset = VoxelLibrary.Get("towers/fighter_jet"); // asset.Mesh / asset.Material for existing renderers
```

Meshes are built with greedy meshing (same-colour faces merged). The material is a clone of a vanilla model material, so lighting and shading match the game.

## Coordinate conventions

- MagicaVoxel uses Z up; Unity uses Y up.
- Mapping: `unity.x = vox.x`, `unity.y = vox.z`, `unity.z = vox.y`.
- Models aren't mirrored. Vanilla models face **+X in Unity** (the biplane flies along its X axis).

## Grounding (grass layer)

The tile's grass covers the lowest ~3.5 voxels around the castle: the grass top is at world y ≈ 0.333, and a voxel is 0.09375 world units after the castle's 0.9375 scale.

- Castle recipes are designed from z = 0, then passed through `VoxCanvas.Grounded()`.
- `Grounded()` lifts the model by 4 voxels and extends every ground-touching column down in its own colour.
- Exception: models whose heights are mechanical. Crow's Nest's platform height is tied to its collider (CrowsNestBehaviour.PlatformY), so it is designed in final coordinates.

## Animation and transparency (evaluated in M6)

**Rigid-part animation works well.** Castle parts are declared in `CastleDef.Parts` (model, voxel position, scale, optional float animation) and appear in the menu background and in the game; game logic finds them with `CastleVisuals.FindPart`.
- Split moving parts into separate models (e.g. `castles/arcane_spire_crystal`).
- Parent them under the castle mesh at a voxel height and move them from a MonoBehaviour: bob, spin, open doors, recoil.
- Cost: one extra mesh per part. Used by the Arcane Spire crystal.

**Frame animation is possible.**
- Several `.vox` frames swapped on a `MeshFilter` (MagicaVoxel supports frames).
- Fine for small things such as flags or flickering flames. Every frame is a full mesh, so keep frames few and models small.

**Glow and light effects work, with no new assets.**
- `LineRenderer` + `Fx.GlowMaterial`: the built-in `Sprites/Default` shader, alpha-blended, colour from vertex/line colours. Used for the mana veins and floor runes.
- Point `Light`s.
- Procedural particle bursts: `Fx.Burst`, using a vanilla particle material.

**Semi-transparent voxels work** (update after testing):
- Glass Fortress: `CastleDef.ModelAlpha` / `Fx.FadeCopy`, the Standard shader in Fade mode (lit). The Fade variant turned out to be included in the build.
- Necropolis ghosts: `Fx.RampTexture` remaps a palette texture to a blue ramp by brightness; drawn with `Fx.GhostMaterial` (unlit `Sprites/Default`, 80% opacity).
- Real custom shaders would need an AssetBundle built in the Unity 2021.1 editor; shaders cannot be compiled at runtime.

Original evaluation notes:
- Shaders loaded at runtime (console `shaders`):
  - `Standard`, used by all voxel meshes, opaque only. Its Fade/Transparent variants are most likely stripped from the build.
  - `Sprites/Default` and `Particles/Standard Unlit`, both alpha-blended.
- A voxel mesh can be drawn semi-transparent with `new Material(Sprites/Default) { mainTexture = palette }` plus an alpha colour.
- It is **unlit**: no sun shading or shadows, so it looks flat next to lit voxels. It also doesn't write depth, so overlapping transparent parts can sort wrongly.
- Good for small effect parts (crystals, ghosts, force fields), not for whole buildings.
- A lit transparent look would need our own shader in an AssetBundle (Unity 2021.1 editor), which is possible but a bigger step.
- Per-voxel alpha from the palette is not used yet. The mesher would have to split opaque and transparent voxels into two meshes.
