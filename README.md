# Treasure Run (Rogue Tower mod)

A BepInEx 5 + Harmony mod for Rogue Tower: a roguelike run mode with treasures, castles and tower ascensions. The design and roadmap are in [PLAN.md](PLAN.md); how the game works inside is in [docs/game-architecture.md](docs/game-architecture.md); the rules for working on the code are in [CLAUDE.md](CLAUDE.md).

This file is the practical guide: how to build, regenerate assets and get every change into the game.

## Requirements

- **Rogue Tower** (Steam) with **BepInEx 5.4 (x86)** installed into the game folder.
- **.NET SDK 8**: it builds the mod (for .NET Framework 4.7.2, through reference assemblies from NuGet) and the tools.
- **Where the game is:** `C:\Program Files (x86)\Steam\steamapps\common\Rogue Tower` by default. If it lives elsewhere, create `Directory.Build.user.props` (gitignored) next to the solution:

  ```xml
  <Project>
    <PropertyGroup>
      <GamePath>D:\Games\Rogue Tower</GamePath>
    </PropertyGroup>
  </Project>
  ```

## Repository layout

| Folder | What it is |
|---|---|
| `src/TreasureRun` | The mod (C#). |
| `src/Shared` | Code shared by the mod and the tools (voxel files, Ley pipe geometry). |
| `models/` | Voxel models (`.vox`, `.json` sidecars, `.txt` data such as the accelerator transformation) and their `.png` previews. Generated by VoxTool. |
| `sounds/` | Sound effects (`.wav`) with analysis (`.png`, `.txt`). Generated by SfxTool. `sounds/ascensions/<ascension id>/` per ascension, `sounds/ui/` for the interface, `sounds/previews/` for review mixes (not deployed, not in git). |
| `tools/VoxTool` | Voxel models from code (`Recipes/`), previews, the transformation generator. |
| `tools/SfxTool` | Sounds from code (`Recipes/`), analysis, review mixes. |
| `tests/TreasureRun.Tests` | Offline tests (no game needed). |
| `docs/` | Design and workflow documents ([voxel workflow](docs/voxel-workflow.md), [sound workflow](docs/sound-workflow.md), [ascension plan](docs/ascension-plan.md), …). |

## Building and deploying the mod

Close the game first: it locks `TreasureRun.dll`, and the copy fails while it runs.

```bash
dotnet build src/TreasureRun -c Release
```

The build ends with a deploy step (`DeployPlugin` in `TreasureRun.csproj`) that copies into `<game>\BepInEx\plugins\TreasureRun\`:

- `TreasureRun.dll` and `.pdb`
- every model file in `models/` (`.vox`, `.json`, `.txt`)
- every sound in `sounds/` (`.wav`, except `sounds/previews/`)

It also **removes** deployed models and sounds whose source no longer exists (after a rename or a move). `models/overrides/` in the game folder (your own replacement models, not in the repository) is left alone.

**Only the build copies anything.** Regenerating a model, the transformation or a sound only writes into the repository; run the build again afterwards, or the game keeps the old copy.

### Getting the change into a running game

| What changed | After the build |
|---|---|
| Mod code (`src/`) | Restart the game. |
| Models, sounds, the transformation file | Press **F6** in a Treasure Run (debug tools on: `Debug.DebugTools` in the config, on by default) to reload them, or restart. Things already on screen (a swapped tower model, a running transformation) keep the old version until they are rebuilt; restarting is the sure way. |

## Regenerating assets

Every pipeline is: **change the recipe → regenerate → build the mod (deploy) → F6 or restart.**

### Models (VoxTool)

Run from `tools/VoxTool`:

```bash
dotnet run -c Release -- build ../../models ascensions/particle/
```

- The last argument is a name prefix (`castles/`, `ascensions/mortar/`, …); without it, everything is rebuilt.
- Each model gets a `.vox`, a `.png` preview and, for tower ascensions, a `.json` sidecar.
- Known quirk: rebuilding `ascensions/particle/` (or everything) writes `beam_turret` slightly differently from the committed one. Restore it with `git checkout models/ascensions/particle/beam_turret.vox models/ascensions/particle/beam_turret.png`.
- More in [docs/voxel-workflow.md](docs/voxel-workflow.md).

### The Particle Accelerator's transformation (VoxTool)

The steps, their lengths and their sounds are code: `tools/VoxTool/Recipes/AcceleratorMorph.cs` (`Steps()`). `TimeScale` at the top multiplies every step's length (the build prints the total at TimeScale 1; for a transformation of T seconds set it to T divided by that total).

Run from `tools/VoxTool`:

```bash
dotnet run -c Release -- morph ../../models
```

- It writes `models/ascensions/particle/accelerator_morph.txt` (the file the game reads). Give a folder as a second argument for a preview sheet of the steps.
- Building `ascensions/particle/` models also writes it, together with the capacitor model.
- Then build the mod and press F6 (the next transformation uses the new file) or restart.
- To check what the game has: the line `timescale …` near the top of `BepInEx\plugins\TreasureRun\models\ascensions\particle\accelerator_morph.txt` must match the one in the repository.
- Then render the review mix again (below), since its timing comes from that file.

### Sounds (SfxTool)

Run from `tools/SfxTool`. SfxTool runs as a built program, so **build it again after editing a recipe**, or the old recipe renders:

```bash
dotnet build -c Release
```
```bash
bin/Release/net8.0/SfxTool.exe build ../../sounds ascensions/particle_accelerator/
```

- The prefix picks the sounds (a folder, or one name); without it, everything is rendered.
- Each sound gets a `.wav`, an analysis `.png` (waveform, spectrogram) and a `.txt` report.
- Then build the mod and press F6 (or restart).
- More in [docs/sound-workflow.md](docs/sound-workflow.md).

#### Review mix of the transformation

```bash
bin/Release/net8.0/SfxTool.exe morphpreview ../../models ../../sounds ../../sounds/previews
```

It mixes the whole transformation the way the game plays it (from `accelerator_morph.txt` and the sounds) into `sounds/previews/`:

- `accelerator_to_core.wav` and `accelerator_to_capacitor.wav` at the speed in the file.
- `*_slow.wav`: the same at TimeScale 2, so every sound can be heard on its own.

Run it again after changing the sounds or the transformation.

### Treasure list

In game, the dev console command `treasuredoc` writes `console/treasures.md` in the plugin folder; copy it to `docs/treasures.md` after treasure changes.

## Testing

- **Offline:** `dotnet test tests/TreasureRun.Tests` (seconds; game logic ports and the mod's pure logic files).
- **In game:** the dev console (`§`, `` ` `` or F10, or the file `BepInEx\plugins\TreasureRun\console\in.txt`, output in `console\out.txt`). `scenario all` runs every scenario; `scenario <name>` one (`scenario accelerator-morph` plays the accelerator transformation both ways and saves frames to `screens/`). `help` lists the commands; [CLAUDE.md](CLAUDE.md) has the most useful ones.
- **Building many at once:** in build mode, hold Shift, click and keep the button pressed: dragging paints the same tower or building on every free cell the cursor passes (a line without diagonal gaps, so Ley Siphons stay connected), each at its usual price. Setting `General.DragToBuild` (on by default; "Shift-drag to build" in the Options menu). `scenario paint-build` checks it (through the same placement code; the mouse itself can't be driven from the console).

## Quick reference

| I changed… | Run | Then |
|---|---|---|
| mod code | `dotnet build src/TreasureRun -c Release` | restart the game |
| a treasure or card (balance) | its spec in `Balance/Specs/ContentSpecs.cs`, then `dotnet test tests/TreasureRun.Tests` | in game: `balance report`, then copy `console/balance.*` to `docs/balance-report.*` |
| the game version (monster data) | `python tools/balance/extract_monsters.py ../Ripped/ExportedProject/Assets` | build the mod |
| a model recipe | VoxTool `build ../../models <prefix>` | build the mod, F6 |
| the transformation (steps, `TimeScale`) | VoxTool `morph ../../models` | build the mod, F6; SfxTool `morphpreview` |
| a sound recipe | `dotnet build -c Release` in `tools/SfxTool`, then SfxTool `build ../../sounds <prefix>` | build the mod, F6; `morphpreview` for transformation sounds |
